De HTML estático a React

Migración a una SPA con React 19 + Vite, Bootstrap y pruebas con Vitest

Integrantes: Ricardo y Cristobal · 2026

El punto de partida

¿Cómo era el sitio en HTML clásico?

  • Un archivo .html por página: index, productos, registro, carrito… (8 archivos).
  • El menú y el footer se copiaban y pegaban en cada página.
  • Navegar con <a href="productos.html"> recargaba toda la página.
  • Las validaciones leían el DOM "a mano":
<!-- JavaScript clásico -->
const rut = document.getElementById('rut').value;
document.getElementById('msg').textContent = 'Error: RUT inválido';

El destino

¿Cómo es ahora con React + Vite?

  • Un solo index.html con un <div id="root"> vacío: React dibuja todo ahí.
  • La interfaz se divide en componentes reutilizables con props y estados.
  • React Router cambia de "página" sin recargar (SPA).
  • Bootstrap 5 entrega el diseño responsivo con su sistema de grid.
  • 10 pruebas unitarias con Vitest + Testing Library.
src/
├─ main.jsx        → monta React e importa Bootstrap
├─ App.jsx         → rutas del sitio (React Router)
├─ components/     → Header, Footer, ProductoCard (props)
├─ pages/          → Home, Productos, Carrito, Registro, Login…
├─ data/           → productos.js (el catálogo como DATOS)
└─ *.test.jsx      → 10 pruebas unitarias

PASO 1 El punto de entrada

ANTES · cada página HTML 
<body>
  <header>…menú repetido…</header>
  <main>…contenido…</main>
  <script src="js/app.js"></script>
</body>
AHORA · un solo index.html 
<body>
  <div id="root"></div>
  <script type="module"
          src="/src/main.jsx"></script>
</body>
// main.jsx — React toma el control del div#root y cargamos Bootstrap
import 'bootstrap/dist/css/bootstrap.min.css';
ReactDOM.createRoot(document.getElementById('root')).render(<App />);

Idea clave: el HTML queda casi vacío; React construye la página con JavaScript.

PASO 2 Componentes: escribir una vez, usar en todas partes

ANTES

El menú y el footer estaban copiados en los 8 archivos HTML.

¿Cambiar un enlace del menú? → editar 8 archivos 😰

AHORA

Un componente es una función que devuelve HTML (JSX).

¿Cambiar el menú? → editar 1 archivo 😎

// App.jsx — Header y Footer se escriben una sola vez
function App() {
  return (
    <BrowserRouter>
      <Header />          <!-- aparece en TODAS las páginas -->
      <Routes>…</Routes>
      <Footer />
    </BrowserRouter>
  );
}

PASO 3 Props: componentes personalizables

Creamos ProductoCard: una sola tarjeta que se personaliza con datos distintos mediante props:

export function ProductoCard({ nombre, precio, imagen, onAgregar }) {
  return (
    <article className="card h-100 shadow-sm">
      <img src={imagen} alt={nombre} />
      <h3>{nombre}</h3>
      <p>Precio: ${precio.toLocaleString('es-CL')}</p>
      {onAgregar && <button onClick={() => onAgregar(nombre)}>
        Añadir al carrito
      </button>}
    </article>
  );
}

Props = "parámetros" del componente: el padre decide qué datos muestra cada tarjeta.

Renderizado condicional: el botón solo aparece si la prop onAgregar existe.

PASO 5 Estado: del DOM "a mano" a useState

ANTES · leer el DOM 
// buscar el input y sacarle el valor
const rut = document
  .getElementById('rut').value;
AHORA · Registro.jsx 
const [rut, setRut] = useState('');

<input value={rut}
       onChange={(e) => setRut(e.target.value)} />
  • El dato vive en el componente (variable de estado), no escondido en el HTML.
  • El mensaje de validación se muestra solo cuando existe: {mensaje && <p>{mensaje}</p>}

Idea clave: el estado es la fuente de la verdad; la pantalla es su reflejo.

PASO 6 Carrito funcional con estado

El carrito pasó de ser HTML fijo a una lista viva que se puede modificar:

const [items, setItems] = useState([…]);

const eliminarProducto = (id) =>
  setItems(items.filter((item) => item.id !== id));

const total = items.reduce(
  (suma, item) => suma + item.precio * item.cantidad, 0
);
  • Eliminar un producto → filter crea una nueva lista → React repinta solo.
  • El total se calcula automáticamente con reduce cada vez que cambia la lista.
  • Carrito vacío → mensaje distinto: No hay productos en el carrito.

Proceso de testeo: mocks y cobertura

MOCKS con vi.fn() 
const agregarMock = vi.fn();
render(<ProductoCard {…p}
  onAgregar={agregarMock} />);

fireEvent.click(boton);

expect(agregarMock)
  .toHaveBeenCalledWith('Procesador Intel i5');

El mock simula la función y registra cómo fue llamada, sin ejecutar la lógica real.

Conclusión

El contenido del sitio es el mismo. Lo que cambió es cómo lo construimos:

  • Componentes + props → escribir una vez, personalizar y reutilizar.
  • Estado (useState) → formularios y carrito reactivos, sin tocar el DOM.
  • Bootstrap → diseño responsivo con su sistema de grid.
  • 10 pruebas + mocks + cobertura → calidad verificable con un comando.
