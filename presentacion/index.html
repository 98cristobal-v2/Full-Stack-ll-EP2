De HTML estático a React

Cómo migramos nuestro sitio web a una Single Page Application

Integrantes: Ricardo y Cristobal · 2026

El punto de partida

¿Cómo era el sitio en HTML clásico?

  • Un archivo .html por página: index.html, productos.html, registro.html, carrito.html…
  • El menú y el footer se copiaban y pegaban en cada página.
  • Navegar con <a href="productos.html"> recargaba toda la página.
  • Las validaciones leían y modificaban el DOM "a mano":
<!-- JavaScript clásico -->
const rut = document.getElementById('rut').value;
document.getElementById('msg').textContent = 'Error: RUT inválido';

El destino

¿Cómo es ahora con React + Vite?

  • Un solo index.html con un <div id="root"> vacío: React dibuja todo ahí dentro.
  • La interfaz se divide en componentes reutilizables.
  • React Router cambia de "página" sin recargar (SPA).
  • El estado (useState) controla formularios y mensajes.
src/
├─ main.jsx        → monta la aplicación en el navegador
├─ App.jsx         → define las rutas del sitio
├─ components/     → Header y Footer (se escriben UNA vez)
└─ pages/          → Home, Productos, Nosotros, Blog,
                          Contacto, Carrito, Login, Registro

PASO 1 El punto de entrada

ANTES · cada página HTML 
<body>
  <header>…menú repetido…</header>
  <main>…contenido…</main>
  <script src="js/app.js"></script>
</body>
AHORA · un solo index.html 
<body>
  <div id="root"></div>
  <script type="module"
          src="/src/main.jsx"></script>
</body>
// main.jsx — React toma el control del div#root
ReactDOM.createRoot(document.getElementById('root')).render(<App />);

Idea clave: el HTML queda casi vacío; React construye la página con JavaScript.

PASO 2 Componentes: escribir una vez, usar en todas partes

ANTES

El menú y el footer estaban copiados en los 8 archivos HTML.

¿Cambiar un enlace del menú? → editar 8 archivos 😰

AHORA

Un componente es una función que devuelve HTML (JSX).

¿Cambiar el menú? → editar 1 archivo 😎

// App.jsx — Header y Footer se escriben una sola vez
function App() {
  return (
    <BrowserRouter>
      <Header />          <!-- aparece en TODAS las páginas -->
      <Routes>…</Routes>
      <Footer />
    </BrowserRouter>
  );
}

PASO 3 JSX = HTML dentro de JavaScript

Casi todo el HTML se puede pegar tal cual… con 4 reglas de conversión:

HTML 
<label for="rut">RUT:</label>
<div class="caja">
<button onclick="validar()">
JSX 
<label htmlFor="rut">RUT:</label>
<div className="caja">
<button onClick={validar}>
  • class → className y for → htmlFor (son palabras reservadas de JS).
  • Las llaves { } insertan JavaScript dentro del HTML: variables, funciones, expresiones.

PASO 4 Navegación: de <a href> a <Link>

ANTES · recarga completa 
<a href="productos.html">
  Productos
</a>

El navegador descarga otra página entera: parpadeo y espera.

AHORA · sin recargar 
<Link to="/productos">
  Productos
</Link>

React Router intercambia el componente al instante.

// App.jsx — el mapa del sitio
<Route path="/"          element={<Home />} />
<Route path="/productos" element={<Productos />} />
<Route path="/registro"  element={<Registro />} />

SPA (Single Page Application): una sola página; el router solo cambia qué componente se muestra.

PASO 5 Formularios: del DOM "a mano" al estado

ANTES · leer el DOM 
// buscar el input y sacarle el valor
const rut = document
  .getElementById('rut').value;
AHORA · useState (Registro.jsx) 
const [rut, setRut] = useState('');

<input value={rut}
       onChange={(e) => setRut(e.target.value)} />
  • El dato vive en el componente (una variable de estado), no escondido en el HTML.
  • Cada tecla actualiza el estado → React repinta solo lo que cambió.

Idea clave: el estado es la fuente de la verdad; la pantalla es su reflejo.

PASO 6 Validación y mensajes: renderizado condicional

La lógica de validación es la misma de antes (RUT de 8–9 caracteres, dominios @duoc.cl, @gmail.com…). Lo que cambia es cómo se muestra el resultado:

ANTES · modificar el DOM 
document.getElementById('msg')
  .textContent = 'El RUT debe tener
   entre 8 y 9 caracteres.';
AHORA · el HTML reacciona al estado 
setMensaje('El RUT debe tener
 entre 8 y 9 caracteres.');

{mensaje && <p>{mensaje}</p>}

Renderizado condicional: {mensaje && <p>…</p>} significa "muestra el <p> solo si hay mensaje". No hay que borrar nada a mano.

PASO 7 Listas: de copiar y pegar a .map()

ANTES · HTML repetido

En productos.html había un <article> copiado por cada producto.

¿Agregar un producto? → copiar, pegar y editar otro bloque HTML.

EN REACT · datos + map() 
{productos.map((p) => (
  <article key={p.id}>
    <h3>{p.nombre}</h3>
    <p>Precio: {p.precio}</p>
  </article>
))}
  • El catálogo se convierte en datos (un array) y React genera el HTML por nosotros.
  • Agregar un producto = agregar un dato, sin tocar el diseño.

Próximo paso natural del proyecto: nuestro Productos.jsx ya está listo para mover sus productos a un array.

Bonus de la migración

Pruebas automáticas (algo imposible en HTML plano)

Antes, probar el formulario significaba abrir el navegador y hacer clic a mano. Ahora, con Vitest + Testing Library, las pruebas se ejecutan solas con npm test:

// Registro.Test.jsx — prueba real del proyecto
fireEvent.change(inputRut, { target: { value: '123' } });
fireEvent.click(botonRegistrar);

expect(screen.getByText(
  'El RUT debe tener entre 8 y 9 caracteres.'
)).toBeInTheDocument();
  • El proyecto incluye 3 pruebas del registro: RUT corto ❌, correo no permitido ❌ y registro exitoso ✅.
  • Si alguien rompe la validación en el futuro, el test lo detecta al instante.

Conclusión

El contenido del sitio es el mismo. Lo que cambió es cómo lo organizamos:

  • Componentes → escribir una vez, reutilizar siempre.
  • SPA con React Router → navegación instantánea, sin recargas.
  • Estado (useState) → la pantalla refleja los datos, sin tocar el DOM.
  • Pruebas automáticas → calidad asegurada con un comando.
